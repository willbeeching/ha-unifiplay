## What's new in 1.4.2

A bug-fix release for direct mode. The only behaviour that changes is how a
manually entered speaker is identified. No new entities, no new services, no
change to the supported Home Assistant floor.

**Restart Home Assistant after updating.** Reloading a config entry does not
reload Python; only a restart picks up the new code.

### Two Audio Ports no longer merge into one device

Audio Ports do not answer the UDP discovery probe, so in direct mode each
manually entered address is identified by connecting to the speaker's own
MQTT broker. Until now the probe took the speaker's MAC from the **first**
`UPL-*/<MAC>/status` topic that broker delivered.

That assumed a broker only carries its own topics. It does not. On three
`UPL-PORT` speakers at firmware 1.1.13, one broker delivered another
speaker's retained status topic **ahead of its own**. Both addresses were
identified as the same speaker, so one of them never appeared, and the
survivor was redialled between the two addresses on every five-minute poll
(#43).

The probe now takes the MAC from the topic its `info` request is answered
on. That reply is live and comes from the speaker itself, while the stray
topic is retained and predates the connection, so a retained message is
never taken as the answer. If a broker shows status topics for several
speakers and no reply arrives, the probe now declines to identify the
address and logs a warning, and the next poll tries again. Guessing is what
merged the two devices.

A new debug line lists every status topic the probe saw and the topic the
reply came on, so the next report like this one carries its own evidence.

Found, fixed and measured by @HawkinsJM (#44) on three Audio Ports at
firmware 1.1.13, entered as manual hosts on a different subnet from Home
Assistant. With the fix, all three appear as separate devices and the
address flapping stops.

### Not verified

- **Why** a broker carries another speaker's status topic. The two speakers
  involved had been in a zone together, and the topic outlived the zone
  being deleted, but zoning has not been shown to be the cause.
- Whether this happens on a `UPL-AMP`. Nothing in this release was measured
  on a PowerAmp. Amps normally answer the UDP probe and never reach this code.
- A broker relaying a peer's **live** `info` events. Replies carry no
  reference to the request that caused them, so the probe tells its answer
  apart by the retain flag alone. Not observed; noted so it is not assumed
  away.

### Verification

Both lanes, the per-module coverage gate, strict typing, formatting,
hassfest, HACS and the protocol guards pass. Four new tests in
`tests/test_discovery.py` reproduce the fault: all four fail against 1.4.1's
probe and pass with this release.

As before, **hardware smoke on both models is the release checklist, not
CI**. The fix above is backed by hardware on three Audio Ports; the rest of
the checklist was not re-run for this release.

### Install

HACS installs from the repository as usual and will offer 1.4.2 as the latest
release. For a manual install, download `unifi_play.zip` and unpack it into
`config/custom_components/`, then **restart** Home Assistant.

The archive is built from the tagged commit with fixed timestamps and file
modes, so rebuilding it from this tag reproduces the published checksum:

```
python scripts/build_release_archive.py
sha256sum -c dist/unifi_play.zip.sha256
```
