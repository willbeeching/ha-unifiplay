## What's new in 1.4.3

A small defensive release on top of 1.4.2. The only behaviour that changes
is what happens when discovery reports one speaker at two addresses at once.
No new entities, no new services, no change to the supported Home Assistant
floor.

**Restart Home Assistant after updating.** Reloading a config entry does not
reload Python; only a restart picks up the new code.

### One speaker is no longer folded onto two addresses

When a discovery pass returned the same speaker at two different addresses,
the integration read the second as the speaker **moving**. It redialled the
speaker at the other address, whatever was really at that address never
appeared, and the only trace in the log was an info line saying the speaker
had moved. That is how one Audio Port vanished in #43, with nothing to say
why.

1.4.2 removed the cause found in #43. This release stops the integration
trusting that situation whatever causes it. One speaker cannot be at two
addresses in the same pass, so when discovery says it is, the integration now:

- keeps the address the speaker already has, or else the first one offered,
  so the order of a sweep cannot move a speaker that is answering fine where
  it is;
- leaves the other address alone for that pass, with no redial;
- logs a **warning** naming the speaker and every address involved.

A speaker offered twice at the **same** address, answering both the
broadcast and a direct probe, is not a collision and behaves as before (#46).

### What this does not cover

A conflicting address that turns up on a **later** poll. Across polls that
looks exactly like a speaker that genuinely changed address, and those are
deliberately followed, since a speaker that moved leaves behind a connection
that still believes it is fine. The address flapping seen in #43 is prevented
by 1.4.2's probe fix, not by this change.

### Verification

Both lanes, the per-module coverage gate, strict typing, formatting,
hassfest, HACS and the protocol guards pass. Two new tests reproduce the
#43 shape: both fail against 1.4.2's coordinator, where the speaker ends up
redialled at the second address, and pass with this release. A third checks
that one address offered twice is not treated as a collision.

**Not verified on hardware.** This is coordinator logic above the discovery
layer, exercised through the test suite. Hardware smoke on both models
remains the release checklist and was not re-run for this release.

### Install

HACS installs from the repository as usual and will offer 1.4.3 as the latest
release. For a manual install, download `unifi_play.zip` and unpack it into
`config/custom_components/`, then **restart** Home Assistant.

The archive is built from the tagged commit with fixed timestamps and file
modes, so rebuilding it from this tag reproduces the published checksum:

```
python scripts/build_release_archive.py
sha256sum -c dist/unifi_play.zip.sha256
```
